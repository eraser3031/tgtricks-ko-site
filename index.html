주요 발견

두 앱 모두 화면에 보이는 레이어를 기준으로 삼아요. 레이아웃은 모델 레이어에 먼저 쓰고, 명시적 애니메이션이 화면을 따라오게 해요. 비공개 API는 꼭 필요할 때만 쓰고, 되도록 ABI를 스스로 점검해요.

  1. 01

    iOS는 UIKit 레이아웃·스크롤을 거의 쓰지 않아요

    채팅 목록에 UITableView을 쓰지 않아요. AsyncDisplayKit 노드, 보이지 않는 UIScrollView, π만큼 뒤집은 목록으로 화면을 직접 만들고, 시스템에서는 스크롤 물리만 빌려요.

  2. 02

    iOS는 시스템 비공개 객체를 직접 다뤄요

    키보드 윈도우, _UIPortalView、_UILiquidLensView, 여러 비공개 KVC 키를 직접 가져와요. 비공개 클래스 이름은 대부분 실행 중에 이어 붙이고, 메서드 시그니처도 스스로 확인해요.

  3. 03

    macOS는 AppKit으로 UIKit 방식을 따라 해요

    TGUIKit은 좌표계를 한꺼번에 뒤집고, 암시적 애니메이션을 끄고, NSTableView 행 높이를 직접 관리해요. 메뉴는 키 윈도우가 되지 않는 윈도우에 직접 그려요.

  4. 04

    비공개 경로는 OS가 바뀌면 조용히 깨져요

    macOS 26.7에서는 공유 메뉴의 selector 이름이 바뀌었고, 지도 뷰 트리에서도 MKZoomSegmentedControl가 사라졌어요. 옵셔널 바인딩으로 막아 두어서 앱이 멈추진 않지만, 커스터마이징이 조용히 사라져요.

렌더링과 미디어

네트워크로 받은 바이트나 카메라 입력이 화면 픽셀과 스피커 소리가 되기까지 전 과정을 따라가요. Lottie와 커스텀 이모지, 비디오 스티커와 디코더, 이미지 코덱, 음성 메시지, 카메라와 편집기를 다뤄요.

렌더링과 미디어 개요 보기
  1. 01

    Lottie 애니메이션 파이프라인

    Telegram iOS와 macOS 클라이언트가 Lottie 애니메이션 스티커와 애니메이션 이모지를 디코딩, 렌더링, 캐시, 스케줄링하고 전력 소모를 제어하는 방식.

  2. 02

    커스텀 이모지와 애니메이션 캐시

    Telegram iOS와 macOS 클라이언트의 커스텀 이모지, 소형 애니메이션 렌더링, 프레임 캐시, 일괄 처리, 디스크 축출 메커니즘을 살펴봐요.

  3. 03

    비디오 스티커, 비디오 디코딩과 스트리밍

    Telegram iOS와 macOS 클라이언트의 비디오 스티커, FFmpeg 디코딩, AV1 연동, 재생하면서 내려받기, HLS 세그먼트 재생 경로를 추적해요.

  4. 04

    이미지 코덱과 썸네일

    Telegram iOS와 macOS 클라이언트의 이미지 업로드 압축, 미니 썸네일, 점진적 표시, 백그라운드 그리기, 이미지 캐시에 대한 연구.

  5. 05

    음성 메시지와 오디오 시스템

    iOS와 macOS 소스에서 음성 메시지의 캡처, Ogg Opus 인코딩, 파형, 재생, 세션 중재, 라우팅, 통화 노이즈 억제를 추적해요.

  6. 06

    카메라, 원형 비디오, 미디어 에디터

    iOS와 macOS 클라이언트가 카메라 캡처, 원형 비디오 녹화부터 미디어 편집, 내보내기, 전송 전 트랜스코딩까지 어디까지 구현했는지 그 경계를 따라가 봐요.

Linear 동기화 엔진

협업 앱의 데이터를 맞춰 주는 Linear Sync Engine(LSE)을 프런트엔드 코드로 역분석한 글을 옮겼어요. 모델 정의부터 부트스트래핑, 트랜잭션, 델타 패킷까지 따라가요.
