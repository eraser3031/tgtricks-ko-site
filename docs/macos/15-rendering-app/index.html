17. GIF 트랜스코더는 극단적으로 짧은 지연을 보정하고, CVPixelBuffer에 직접 그리기

#15-17 · TelegramSwift · AppKit · 검증 방식: 소스 분석

소스: TelegramSwift:packages/TGGifConverter/Sources/TGGifConverter/TGGifConverter.m L185–L255

무엇을 했나요:

  • GIF의 클램프(범위 제한)되지 않은 지연을 먼저 써요.
  • 11 ms 미만의 지연은 모두 100 ms로 보정해요.
  • 픽셀 풀에서 ARGB 버퍼를 가져와 Core Graphics가 그 버퍼에 직접 쓰게 해요.

왜 이렇게 했나요: 일부 GIF는 비현실적으로 짧은 지연을 보고해요. 그대로 재생하면 CPU 사용률이 높아지거나 프레임 레이트가 잘못돼요. 인코더가 쓸 수 있는 CVPixelBuffer에 직접 그리면 불필요한 이미지 중간 전달을 피해요.

핵심 코드 발췌

18. 소프트웨어 비디오 미리 보기는 CVPixelBuffer를 잠근 뒤 vImage로 한 번에 스케일하기

#15-18 · TelegramSwift · AppKit · 검증 방식: 소스 분석, REA 바이너리 · 태그: 성능과 메모리

소스: TelegramSwift:packages/TelegramMedia/Sources/SoftwareVideoSource.swift L26–L50

무엇을 했나요:

  1. 미리 보기 경로가 디코딩된 프레임의 픽셀 메모리를 직접 잠가요.
  2. vImageScale_ARGB8888로 목표 backing scale(화면 배율)까지 스케일해요.
  3. 마지막에야 CGImage로 감싸요.

왜 이렇게 했나요: 이 경로는 중간 NSImage와 여러 겹의 드로잉 컨텍스트를 만드는 일을 피해요. vImage(Apple의 이미지 처리 라이브러리)는 소스와 대상의 stride(한 행의 바이트 길이)를 올바르게 처리할 수 있어요. 단일 프레임 정적 미리 보기를 만들기에 알맞아요.

핵심 코드 발췌

대가와 위험: malloc을 쓰는데 이 코드 조각에는 명시적인 free(memoryData)가 없어요. generateImagePixel이 이후 복사한 뒤 이 블록을 해제하는지는 미검증이에요. 해제하지 않는다면 미리 보기를 자주 호출할 때 메모리가 누수돼요.

증거 체인 #15-18(릴리스됨 · 계속 사용 가능)

  • 소스 분석: TelegramSwift 고정 커밋에서 행 단위로 확인했어요. 소스 위치 총 1곳.
