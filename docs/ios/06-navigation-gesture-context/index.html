1. 비공개 _UIPortalView로 같은 콘텐츠를 레이어 간에 표시하기

#06-01 · Telegram-iOS · UIKit · 리포트 선정 06-1 · 검증 방식: 소스 분석 · 태그: 비공개 API

무엇을 했나요: 원본 뷰를 따라 하는 Portal 뷰(원본과 같은 콘텐츠를 다른 계층에 보여 주는 뷰)를 하나 만들어요.

  • 원본 뷰의 위치와 변환을 그대로 따라 해요.
  • alpha는 따라 하지 않고, 히트 테스트(터치가 어느 뷰에 닿았는지 찾는 과정)도 받지 않아요.
  • PortalView는 원본 뷰를 sourceView에 넣고, 원래 계층 인덱스 자리에 강제로 다시 끼워 넣어요.

왜 이렇게 했나요: 컨텍스트 메뉴는 메시지 말풍선을 메뉴와 내비게이션 바 위에 보여 줘야 해요. 방법마다 이래요.

  • 실제 말풍선을 직접 옮기면 채팅 트리가 깨져요.
  • 일반 스냅샷은 콘텐츠를 계속 재생하지 못하고 상태 변화에도 반응하지 못해요.
  • Portal은 두 계층에서 같은 콘텐츠를 보여 줄 수 있어요.

아래 도표는 원본 말풍선과 Portal 미러가 어떻게 연결되는지 보여 줘요.

핵심 코드 발췌

비공개 API 난독화 복원: 배열을 이어 붙이면 _UIPortalView가 돼요. @"_" + @"UI" + @"Portal" + @"View"와 NSClassFromString을 근거로 확인했어요. 관련 속성으로 matchesPosition, matchesTransform, allowsHitTesting이 있어요.

대가와 위험: 공개되지 않은 UIKit API예요. App Store 심사와 시스템 호환성 위험이 아주 높아요. 클래스가 없으면 nil을 돌려줘요.

증거 체인 #06-01(iOS 바이너리 미검증)

  • 소스 분석: Telegram-iOS 고정 커밋에서 행 단위로 확인했어요. 소스 위치는 모두 2곳이에요.
  • 리포트 요약(구현 방법): NSClassFromString으로 클래스 이름을 이어 붙이고, 속성은 버전 가드를 두고 설정해요.
  • 바이너리 검증: 하지 않았어요. App Store 배포 IPA는 FairPlay로 암호화돼 있어서 복호화된 실행 파일을 합법적으로 얻을 수 없어요.

  • 스냅샷만 옮기면 동적 콘텐츠를 잃어요.

아래 도표는 실제 콘텐츠와 Portal 미러가 애니메이션 앞뒤로 움직이는 순서를 보여 줘요.

3. 투명 배경에 1×1 이미지를 넣어 “보이지만 눌리지 않는” 메뉴 바깥 탭 고치기

무엇을 했나요: 메뉴 배경 레이어는 색이 .clear여도 완전히 투명한 contents(레이어가 그리는 이미지)를 가져요. 그래서 배경 레이어가 계속 터치 전달에 참여해요. 그 결과 메뉴 바깥의 탭을 받아 메뉴를 닫을 수 있어요.

5. 퇴장 중에 presentation layer로 착지점 다시 지정하기

#06-05 · Telegram-iOS · UIKit · 검증 방식: 소스 분석 · 태그: Core Animation

소스: Telegram-iOS:submodules/TelegramUI/Components/ContextControllerImpl/Sources/ContextControllerExtractedPresentationNode.swift L2271–L2295

무엇을 했나요: 메뉴가 퇴장하는 동안 원본 메시지의 높이가 바뀌어도 전체 레이아웃을 다시 돌리지 않아요.

대신 presentation()(화면에 지금 보이는 상태를 담은 레이어)과 모델 레이어(최종 값을 담은 레이어)의 차이(잔차)를 읽어요. 그리고 안정적인 key로 bounds.origin.y의 가산 애니메이션 하나를 교체하고, 남은 시간만 써요.

왜 이렇게 했나요: 퇴장 중에는 반응 행이 바뀌어서 원본 메시지가 위로 올라갈 수 있어요. 이때 방법마다 결과가 달라요.

  • 일반적인 재레이아웃: 말풍선이 옛 목표로 튀게 만들어요.
  • position.y를 다시 내보내기: 완료 콜백이 달린 메인 애니메이션을 방해해요.
  • 따로 둔 bounds.origin.y: 메인 애니메이션의 의미를 지켜 줘요.

핵심 코드 발췌

대가와 위험: 이 로직은 Core Animation의 모델 레이어와 프레젠테이션 레이어 차이에 크게 기대요. from == to는 피해야 해요. 그렇지 않으면 애니메이션이 실행되지 않거나 콜백이 오지 않아요. 유지 보수 비용이 높아요.
